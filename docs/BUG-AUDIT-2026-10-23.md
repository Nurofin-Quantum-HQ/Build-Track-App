# BuildTrack bug audit — 23 Oct 2026

Read-only audit of `feat/premium-redesign-v2` (mobile) + backend `fix/role-permission-checks`, after testers reported:
Reports showing zeros after adding entries, daily-update screen scroll/submit broken, Kannada shown in English letters.
Severity: **B** = blocker, **M** = major, **m** = minor. Status column is filled in as fixes land.

## A. Tester complaints — root causes

| # | Sev | What the user sees | Root cause | Status |
|---|---|---|---|---|
| A1 | B | After Add More / Edit / Payment / Delete / any save, Reports shows ₹0 everywhere | Redesign dropped the Reports picker's `setSelectedProject` (main had it). Later `ProjectProvider.load()` refills the shared entry list with the *global* project, Reports filters by its own project → empty. Three unawaited reloads race on one list (report.dart `_applyProject`, `.then` after Add More, save screens) | |
| A2 | B | Zeros stay even after restart | `fetchMaterials` swallows every error and returns `[]`, which is saved to cache | |
| A3 | M | Saving from + jumps to Reports, and Reports narrows to that entry's floor/phase/activity | Save screens `pushNamedAndRemoveUntil('/reports')` for `view_inventory` users; Reports copies global floor/phase/activity into its filters | |
| A4 | M | Daily-update screen: sections blank-then-slide while scrolling, keyboard closes in Notes, janky | Lazy `ListView` + entrance animation on every section (re-runs on every scroll-in); unkeyed sections shift; photos re-decoded every frame; Submit bar hidden behind keyboard | |
| A5 | B | Daily update from a task: "Could not save… ask an admin" with no request sent | Task's project not in the user's local project list → returns false before calling the server; tasks already marked Completed before the save | |
| A6 | B | Daily update / Mark done / budget save always fails on some projects | App sends `buildingType.mainType: ''`; backend enum rejects it (400) | |
| A7 | M | "Progress updated" but notes/photos lost, or the wrong activity marked done | Activity list from default catalogue, task activityId ignored, name match across phases, fallback saves only `progress` | |
| A8 | M | Mark as Done never moves project progress | `manualProgress` always sent, overrides calculation | |
| A9 | B | Kannada/Tamil receipt in English letters | Fix exists on backend branch `fix/esign-receipt-native-script` but was never merged/deployed. Plus: dead `transliterate()`, stamp date in English/UTC, category/payment values untranslated | |

## Not a bug / product decisions
- Non-admins can't delete their own account (backend 403) — may matter for App Store review.
- Kannada voice input: speech is `en_IN` only.
- Exported PDFs can't show Kannada/Tamil text users type (no Indic font; `pdf` package shaping is limited).

## Fix status (24 Oct)
All items in A–F fixed except where noted. App: `feat/premium-redesign-v2`; backend: `fix/oct23-testing` (includes the
permission checks and the Kannada/Tamil receipt fix — deploy this one branch).

Verified on screen against a local backend (web build):
- A1: Reports on Lakeside Villas → row → Add More → Save → back on Reports, same project, new row on top, Total billed
  +₹94,500 (was ₹0 everywhere).
- A4–A6: Update progress scrolls with every section drawn; Mark as Done & Submit saves on a project without a building
  type; notes stored; project progress auto-calculated (1/5 = 20%).
- A9: receipt page renders Kannada/Tamil script with Noto fonts, no Latin-letter text.
- B9: dates show correctly (were all "today").
- Found during verification and fixed: entry saves failed on web because the offline request id used `nextInt(1 << 32)`.

Open / follow-ups:
- B8: daily updates still send the whole `selectedPhases` array (backend replaces it wholesale); a per-activity endpoint
  would stop re-sending photos.
- C10 provision `overseesRoles` not API-tested (free-plan user limit).
- Ask AI with "All projects" still asks about the app's selected project.
- Production data: run `node scripts/migrate_dates_transactionId.js` (dry run) then `--apply`, and
  `scripts/grant_assign_tasks_to_supervisors.js --apply`, after deploying the backend.
- Not testable here: iOS login (D3), push unregister on a device (D5), real Cloudinary receipt upload (B4), SES email links.
